# 1. 이미지 압축

## 1.1 기능 개요

### 한 문장 정의
사용자가 이미지를 업로드하기 전 클라이언트 단에서 자동으로 이미지를 최적화하여 업로드 시간을 단축하고 서버 부하를 줄이는 기능

### 핵심 가치 제안
| 항목 | 내용 |
|------|------|
| **문제** | 고해상도 스마트폰 사진(5-15MB)으로 인한 긴 업로드 시간, 사용자 이탈 발생 |
| **해결** | 클라이언트 사이드 압축으로 업로드 시간 70-80% 단축 |
| **차별점** | 품질 저하 없이 AI 분석에 최적화된 해상도로 자동 변환 |

### 대상 사용자
- 모바일 환경에서 서비스를 이용하는 사용자 (전체의 85% 예상)
- 네트워크 환경이 불안정한 사용자

---

## 1.2 사용자 시나리오

### 주요 시나리오 (Happy Path)

**시나리오 1: 일반 이미지 업로드**
```
1. 사용자가 "패션 평가" 화면에서 "사진 선택" 버튼 클릭
2. 갤러리에서 전신 사진(12MB, 4032x3024) 선택
3. [자동] 압축 진행 표시 ("이미지 최적화 중..." 0.5-2초)
4. [자동] 1.2MB, 1920x1440으로 압축 완료
5. 미리보기 화면에 압축된 이미지 표시
6. 사용자가 "업로드" 버튼 클릭
7. 3초 내 업로드 완료 (기존 15초 → 3초)
```

**시나리오 2: 저화질 이미지 처리**
```
1. 사용자가 저화질 이미지(640x480, 200KB) 선택
2. [자동] 압축 스킵 (이미 최적화된 상태로 판단)
3. "이미지 품질이 낮아 분석 정확도가 떨어질 수 있습니다" 안내
4. 사용자가 계속 진행 또는 다른 사진 선택
```

### 예외 시나리오 (Edge Case)

**예외 1: 압축 실패**
```
1. 지원하지 않는 포맷(TIFF, RAW) 업로드 시도
2. "지원하지 않는 이미지 형식입니다. JPG, PNG, HEIC 파일을 선택해주세요" 안내
3. 파일 선택 화면으로 복귀
```

**예외 2: 메모리 부족 (저사양 기기)**
```
1. 매우 큰 이미지(30MB+) 압축 시도 시 메모리 부족
2. 서버 사이드 압축으로 폴백
3. "처리 중입니다. 잠시만 기다려주세요" (추가 2-3초 소요)
```

## 1.4 기술 설계 명세

### 압축 파라미터

| 항목 | 값 | 근거 |
|------|------|------|
| 목표 해상도 | 1920px (긴 변 기준) | GPT-4 Vision 최적 입력 크기 |
| 최소 해상도 | 1280px | AI 분석 정확도 유지 임계값 |
| 목표 파일 크기 | 1.5MB 이하 | 3G 환경에서 5초 내 업로드 |
| 압축 품질 | 85% (JPEG) | 시각적 품질 저하 최소화 |
| 지원 포맷 | JPG, PNG, HEIC, WebP | 주요 모바일 카메라 포맷 |
| 출력 포맷 | JPEG | 범용성 및 압축 효율 |

### 기술 스택

```javascript
// 클라이언트 사이드 압축 라이브러리
- browser-image-compression (권장)
  - 장점: Web Worker 지원, EXIF 보존
  - 번들 크기: ~50KB gzipped

// 대안
- Compressor.js
- pica (고품질 리사이징)
```

### 압축 로직 플로우

```
[이미지 선택]
      │
      ▼
[메타데이터 추출]
   - 크기, 포맷, 방향
      │
      ▼
[압축 필요 여부 판단]
   - 크기 > 2MB OR 해상도 > 1920px?
      │
   ┌──┴──┐
   No    Yes
   │      │
   ▼      ▼
[스킵]  [Web Worker에서 압축]
   │      │
   │      ├── 리사이징
   │      ├── 품질 조정
   │      └── 포맷 변환
   │      │
   └──────┴─────▶ [미리보기 표시]
                        │
                        ▼
                  [업로드 진행]
```

### API 명세

```typescript
// 클라이언트 함수
interface ImageCompressionOptions {
  maxSizeMB: number;        // 최대 파일 크기 (기본: 1.5)
  maxWidthOrHeight: number; // 최대 해상도 (기본: 1920)
  useWebWorker: boolean;    // Web Worker 사용 여부 (기본: true)
  preserveExif: boolean;    // EXIF 보존 여부 (기본: true)
}

async function compressImage(
  file: File, 
  options?: ImageCompressionOptions
): Promise<{
  compressedFile: File;
  originalSize: number;
  compressedSize: number;
  compressionRatio: number;
}>
```

# 2. 다중 이미지 분석

## 2.1 기능 개요

### 한 문장 정의
여러 장의 코디 사진을 한 번에 업로드하여 일괄 분석하고, 각 코디 간 비교 및 종합 스타일 진단을 제공하는 기능

### 핵심 가치 제안
| 항목 | 내용 |
|------|------|
| **문제** | 하나씩 업로드/분석하는 번거로움, 전체 스타일 패턴 파악 불가 |
| **해결** | 최대 10장까지 일괄 업로드, 개별 분석 + 종합 분석 제공 |
| **차별점** | 단순 개별 평가가 아닌 "스타일 일관성" 및 "다양성" 종합 진단 |

### 대상 사용자
- 본인의 스타일 패턴을 파악하고 싶은 사용자
- 여러 코디 중 베스트를 선택하고 싶은 사용자 (소개팅, 면접 등)
- 옷장 정리/스타일 리뉴얼을 고민하는 사용자

---

## 2.2 사용자 시나리오

### 주요 시나리오 (Happy Path)

**시나리오 1: 일주일 코디 분석**
```
1. 사용자가 "다중 분석" 버튼 클릭
2. 갤러리에서 7장의 코디 사진 선택
3. [자동] 각 이미지 압축 (병렬 처리)
4. "7장의 코디를 분석합니다" 확인 화면
5. [선택] 분석 목적 선택: "일상 코디 패턴 분석"
6. AI 분석 진행 (약 30-45초)
   - 개별 분석: 각 이미지별 평가
   - 종합 분석: 스타일 패턴 도출
7. 결과 화면:
   - 캐러셀로 개별 결과 확인
   - 종합 진단 카드
   - 베스트 코디 / 개선 필요 코디 하이라이트
```

**시나리오 2: A/B 비교 (2장)**
```
1. 사용자가 "오늘 뭐 입지?" 상황에서 2장 선택
2. 상황 입력: "첫 소개팅"
3. AI가 두 코디를 비교 분석
4. 결과: "A 코디가 더 적합합니다" + 상세 이유
```

### 예외 시나리오 (Edge Case)

**예외 1: 이미지 수 초과**
```
1. 사용자가 15장 선택 시도
2. "최대 10장까지 선택 가능합니다. 5장을 제외해주세요" 안내
3. 선택 해제 UI 제공
```

**예외 2: 비의류 이미지 포함**
```
1. 음식 사진이 섞여 있는 경우
2. 개별 이미지 검증 후 "코디 사진이 아닌 이미지가 포함되어 있습니다" 안내
3. 해당 이미지 제외 옵션 제공
```

│
├── 4. 스타일 컨텍스트
│   ├── TPO 적합성
│   └── 트렌드 반영도
│
└── 5. 액션 아이템

# 8. 시즌별/상황별 추천

## 8.1 기능 개요

### 한 문장 정의
현재 계절과 사용자가 선택한 상황(TPO)에 맞는 최적의 코디를 선제적으로 추천하는 기능

### 핵심 가치 제안
| 항목 | 내용 |
|------|------|
| **문제** | 매번 "오늘 뭐 입지?" 고민, 상황에 맞는 옷 선택 어려움 |
| **해결** | 계절 + 상황을 조합한 맞춤 코디 큐레이션 |
| **차별점** | 사용자의 보유 아이템 + SIT 유형 기반 실현 가능한 추천 |
