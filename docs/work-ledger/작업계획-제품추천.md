# 스타일 추천 + 제품 추천 병행

> 코디 추천 시 스타일(아이템·색상·이유)과 함께 제품 추천을 병행합니다.  
> **Phase 1**: 목업 데이터로 UI·API 형태 확립 → **Phase 2**: DB 또는 외부 API 연동.

---

## 1. 목표

- 스타일 추천(기존)과 **제품 추천**을 한 흐름에서 제공.
- 추천 상세(상의/하의/신발/액세서리) 각 카테고리별로 대표 제품 예시 노출.
- 초기에는 **목업 데이터**로 화면·API 계약을 고정하고, 차후 DB 또는 쇼핑 API로 교체 가능하도록 설계.

---

## 2. 수행 계획

| # | 작업 | 산출물 | 단계 |
|---|------|--------|------|
| 1 | 제품 타입·목업 데이터 정의 | `shared` 타입, 서버 목업 목록(카테고리별) | Phase 1 |
| 2 | 추천 API 응답에 제품 목록 부착 | GET/POST 추천 응답에 `products` 필드(카테고리별 배열) | Phase 1 |
| 3 | Recommend 페이지에 제품 추천 UI | 추천 상세 다이얼로그 내 "추천 제품" 섹션 또는 카드별 제품 목록 | Phase 1 |
| 4 | (차후) 제품 소스 전환 | DB 테이블 또는 외부 API 연동 시 목업만 교체 | Phase 2 |

---

## 3. 데이터 설계 (Phase 1)

- **Product** (공통 타입): `id`, `name`, `brand?`, `price?`, `imageUrl?`, `link?`, `category`
- **추천 응답 확장**: 기존 `Recommendation` + `products?: { top: Product[]; bottom: Product[]; shoes: Product[]; accessory: Product[] }`
- DB 스키마 변경 없음. `products`는 API 레이어에서 목업으로 붙여서 반환.

---

## 4. 실행 순서

1. 공통 타입 및 서버 목업 구현
2. POST `/api/recommendations` 응답·GET `/api/recommendations/:id` 응답에 `products` 부착
3. 프론트 `Recommendation` 타입 확장 및 추천 상세 다이얼로그에 제품 영역 UI 추가
